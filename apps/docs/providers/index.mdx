MDScribe hat keinen fest eingebauten KI-Dienst. Der Administrator verbindet die Instanz mit einem
oder mehreren **Providern** (Cloud-API, vertraulicher Dienst oder lokaler Server) und wählt daraus
die Modelle, die MDScribe verwendet. Ohne Verbindung findet keine Generierung statt.

Alles geschieht unter **Admin → Systemeinstellungen → KI-Provider & Modelle**, mit den Reitern
**Verbindungen**, **Modelle**, **AI Vorlagen** und **Brief-Baukasten**.

## Welcher Provider passt?

Die Wahl ist vor allem eine Datenschutz-Abwägung:

| Wenn Sie … | … nutzen Sie | Datenweg |
| --- | --- | --- |
| Daten nicht aus dem eigenen Netz lassen wollen | [Lokale Modelle](/providers/local) | MDScribe → eigener Server |
| Cloud-GPUs mit technisch erzwungener Vertraulichkeit wollen | [Private Provider](/providers/private) (Tinfoil, Privatemode) | MDScribe → verschlüsselt in eine attestierte Enclave |
| viele Modellfamilien vergleichen wollen | [OpenRouter](/providers/openrouter) | MDScribe → OpenRouter → Modellanbieter |
| einen bestimmten Anbieter vertraglich nutzen | [OpenAI](/providers/openai), [Anthropic](/providers/anthropic), [Workers AI](/providers/workers-ai) | MDScribe → Anbieter |
| einen anderen Dienst mit OpenAI-Schnittstelle anbinden | [OpenAI-kompatibel](/providers/openai-compatible) | MDScribe → frei gewählter Endpunkt |

### Alle Protokolle

| Protokoll im Dialog | Zweck |
| --- | --- |
| `OpenAI-kompatibel (llama.cpp / vLLM / LM Studio)` | Jeder Server mit OpenAI-Chat-Completions-API; auch Ollama und der Privatemode-Proxy |
| `OpenRouter` | Aggregator für viele Anbieter |
| `Vercel AI Gateway` | Gateway für viele Anbieter; mit Plus fordert MDScribe hier Zero Data Retention an |
| `OpenAI`, `Anthropic` | Direkte Anbieter-APIs |
| `Tinfoil (vertrauliche Inferenz)` | Vertrauliche Inferenz mit Attestierung |
| `Cloudflare Workers AI` | Open-Weight-Modelle im Cloudflare-Konto |
| `OCR HTTP (selbst gehostet)`, `Mistral OCR (native Dokumenten-API)`, `Privatemode OCR (verschlüsselt, DeepSeek OCR 2)` | Nur für das Dokumenten-Modell: Text aus PDFs und Bildern |

## Standardmodelle

Im Reiter **Modelle** legt die Karte **Standardmodelle** fest, welches Modell welche Aufgabe
übernimmt:

| Rolle | Aufgabe |
| --- | --- |
| **Standard-Modell** | Erzeugt immer die finale Antwort |
| **MDScribe Agent (Beta)** | Steuert den Agent im Brief-Baukasten, wenn das Standard-Modell das nicht übernimmt |
| **Dokumenten-Modell** | Liest PDFs und Bilder zu Text aus (OCR-Dienst oder Vision-Modell) |
| **Audio-Modell** | Transkribiert Audioaufnahmen zu Text |
| **Entscheidungsmodell** (optional) | Beantwortet beim Ausfüllen einfache Fragen (Ja/Nein, Auswahl, Datum, Zahl) vor dem Standard-Modell; unsichere Fälle gehen weiter an das Standard-Modell |

Unter **Fähigkeiten des Standard-Modells** haken Sie an, was das Standard-Modell selbst kann:
`Text` (immer), `Dokumente`, `Audio`, `Agent (Beta)`. Angehakte Eingaben gehen direkt an das
Standard-Modell; die anderen werden vorher vom zuständigen Modell zu Text verarbeitet:

Das Audio-Modell arbeitet wahlweise **Direkt** (Aufnahme ohne Prompt an den
Transkriptions-Endpunkt) oder **Multimodal mit Prompt** (Aufnahme plus Transkriptions-Prompt an ein
audiofähiges Chat-Modell).

Für Modelle mit Reasoning-Unterstützung lässt sich pro Standardmodell die Reasoning-Stufe setzen.

## Modelle synchronisieren

Beim Anlegen einer Verbindung und bei jedem manuellen Aktualisieren liest MDScribe die Modellliste
des Providers ein und speichert sie. Zur Laufzeit wird die Liste nicht live abgefragt.

## Schlüssel und Sicherheit

- API-Schlüssel werden mit `BETTER_AUTH_SECRET` verschlüsselt in der Datenbank gespeichert und nie
  an den Browser ausgeliefert, auch [nutzereigene BYOK-Schlüssel](/providers/byok).
- Es gibt keinen eingebauten Ersatz-Provider.
- Welche Datenschutz-Eigenschaften eine Generierung hat, hängt vom Provider ab; siehe die einzelnen
  Seiten und [KI-Datenfluss](/privacy/ki-datenfluss).
